#-------------------------------------------------
문제
 - 여행자가 여러 숙소의 가격과 편의 시설을 비교하려면 
   상세페이지를 반복해서 이동해야한다.

해결
 - 선택한 숙소3개의 가격,평점,주차,조식정보,환불,취소여부 한
   화면에서 비교한다.

완료기준
 - 숙소를 선택하고 '비교하기'를 누르면 비교표가 표시된다.

AI - 채팅창 
 부산에서 부모님이랑 묵을 호텔 찾아줘 1박 15만원 이하이고
주차장은 꼭 있어야해!

필요한 화면
메인페이지 
 - 필수
 - 역할: 검색, 카테고리,인기숙소,인기 여행 지역

상세페이지
 - 필수
 - 사진,편의시설,객실,위치정보(주소를 크게보이게하자),리뷰
   취소와 환불

비교표
 - 필수(핵심)
 - 선택한 숙소3개를 한 화면에서 비교(핵심)
   가격,평점,주차,조식정보,환불,취소여부
 
Ai채팅
 - 필수
 - 채팅을 입력하면 숙소 추천 

숙소목록 
 - 필수 
 - 채팅창이랑 같이 보여줄지? 따로 팝업형으로 보여줄지 결정
 - 검색/필터결과,비교담기

지도
 - 만약 비교표에 관광지가 있다면 표시(필수)
                     없다면 안 표시(선택)

2. 폴더 구조 생성 
 [패키지구조]
 메인 클래스(@SpringBootApplication)가 있는 패키지를 먼저 찾아서 알려주고, 그 패키지 바로 아래에 하위 패키지 7개를 만들어줘.
메인 클래스 위치는 절대 옮기지 마.

만들 패키지 (이름은 소문자 그대로):
- controller   : 요청을 받고 응답하는 곳
- service      : 비즈니스 로직 
- repository   : DB 조회 (JPA)
- entity       : DB 테이블과 연결되는 클래스
- dto          : 프론트와 주고받는 요청/응답용 클래스
- config       : 설정 클래스 (CORS, Swagger)
- exception    : 공통 에러 처리 (GlobalExceptionHandler)
 폴더만 만들고 다른거는 절대 건드리지마! 기능만들지마!
 
3. 개발 순서에 의해서  entity부터 생성
 [accommodation entity]
  accommodation.java 하나만 만들어줘.
  다른 엔티티는 만들지마! 현재 데이터베이스는 mysql
 - id: Long, @Id, @GeneratedValue(strategy = GenerationType.IDENTITY)
- 필드는 아래 그대로 (이름과 타입 변경 금지, 오타 주의):

 String  name           // 숙소명
  String  type           // 호텔/펜션/풀빌라/리조트/게스트하우스

  int     originalPrice  // 1박 정가

[이번 조각: AccommodationRepository]
repository 패키지에 AccommodationRepository.java 하나만 만들어줘.

규칙:
- 클래스가 아니라 interface로 만들고, JpaRepository<Accommodation, Long>을 상속해.
- 메서드는 아래 1개만 추가해 (쿼리 메서드 이름 규칙 사용, @Query 금지):
  리뷰 수가 많은 순으로 상위 4개를 조회하는 메서드. 이름은 findTop4ByOrderByReviewCountDesc.
  (메인 화면 "이번 주 인기 숙소"용)
- 목록 필터, 비교용 메서드는 아직 만들지 마. (필터는 5단계, 비교는 JpaRepository의 findAllById를 쓸 예정)
